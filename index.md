# Writing Spec Kit

A structured workflow for creative and expository writing, modeled on the software delivery spec kit (contract → plan → implement → review → reflect). All linked files already exist — this index is the entry point.

---

## The Workflow

### Phase 0 — Contract
*Before writing anything: what is this piece, who is it for, what is the one thing it must land?*

Use: [[contract-template]]

Questions to answer before drafting:
- What genre is this? (expository / rhetorical / memoir / hybrid)
- What is the organizing logic? (argumentative / spatial / associative / temporal)
- Who is the reader and what do they need to leave with?
- What is the one sentence this piece must earn?
- What are the protected elements — voice, image, or argument — that must survive revision?

---

### Phase 1 — Plan
*Argument map, beat sheet, or outline. A commitment to what goes where and why.*

- For expository: a proposition hierarchy (parent claim → supporting claims → definitions needed)
- For rhetorical/essay: a beat sequence with the mode of each beat named (Im / De / Na / Mu / Pr / CC / Cl — see [[skills-quick-ref#Skill 6]])
- For long-form/zine: use the existing beat sheet at `Writing Projects/Zine/_rhetorical/index.md`

Rule: do not write prose until the framing question and scope are locked.

---

### Phase 2 — Implement
*Draft against the brief. Resist the urge to revise while drafting.*

Touchstones for quality:
- Rhetorical/prose: [[touchstones/rhetorical-touchstone]] (pine-bark-final2)
- Expository: [[touchstones/expository-touchstone]] (reference.md structure)

Chronic failure mode for this writing: losing the concrete anchor while elaborating the abstraction, or over-explaining the spiritual register at the expense of the image.

---

### Phase 3 — Audit
*Run before section-by-section revision. Catches consistency problems across the whole document.*

Use: `workflows/audit-prompt.md`

Produces:
- Term map (every key term, every section it appears, its role)
- Proposition map (key claims and where they recur)
- Poetic phrase map (phrases that must appear exactly once)
- Prioritized consolidation report with owning sections named

---

### Phase 4 — Revise
*Section-by-section revision using the appropriate skill(s).*

Use: `workflows/revision-prompt.md` (9-step protocol)
Skill selection: [[skills-quick-ref]]

Which skill to use:
| Situation | Skill |
|-----------|-------|
| Reduce a draft to its logical core | Skill 1: Expository Distillation |
| Merge two expository files | Skill 2: Expository Consolidation |
| Sharpen an essay or prose poem | Skill 3: Rhetorical Revision |
| Merge two rhetorical drafts | Skill 4: Rhetorical Consolidation |
| Decompose before expository merge | Skill 5: Vectorial Analysis — Expository |
| Decompose before rhetorical merge | Skill 6: Vectorial Analysis — Rhetorical |
| Order and assemble long-form piece | Skill 7: Sequence and Assembly |

Full skill definitions: `Writing Projects/writing-skills.md`

---

### Phase 5 — Review
*Does the draft fulfill the contract?*

Checks:
- Is the argument coherent from the contract's proposition?
- Does the voice hold from the register established at the opening?
- Does the ending earn its weight — or does it explain what the piece already showed?
- Are all concrete images still intact, or did revision abstract them away?
- Read aloud: where does pace collapse, where does a transition feel like a seam, where does the piece peak too early or too late?

---

### Phase 6 — Reflect
*What did the piece resist? Where did the plan break down? What would you change about the contract if starting again?*

This is where the real craft learning lives. Add to [[decision-rules]] if a new rule emerged.
